# Essential Tools
#
# Windows 10 ships OpenSSH 8.1p1, from 2019. This package installs 10.x under
# C:\Program Files\OpenSSH. It matters because in this setup SSH is not an
# accessory: it is how the Unix hosts are worked on. And 8.1 predates default
# changes that have already bitten - CheckHostIP became "no" in 8.5.
#
# "Preview" is a historical name; it is the channel Microsoft uses to ship
# OpenSSH newer than the built-in one. After installing, check that the PATH
# picks up the new one:  ssh -V   must say 10.x, not 8.1p1.
Microsoft.OpenSSH.Preview
Git.Git
GitHub.cli
Microsoft.VisualStudioCode

# Code Editors
#
# Both are here on purpose: Sublime to edit and navigate code, Notepad++ for
# what you open and close on Windows -- a log, a .reg, a blob of XML. The
# Notepad++ id carries the '+' twice because publisher and package share the
# name; checked against the catalogue manifest, not against an aggregator.
#
# WATCH OUT with Sublime Text 4: this package installs the PORTABLE variant. It
# downloads a .zip and registers command-line aliases -- `subl` and
# `sublime_text` land on the PATH -- but it creates NO Start menu shortcut and
# no entry under Programs and Features.
#
# Not avoidable from here. Checked on 2026-09-10 with `winget search sublime`:
# Sublime Merge and Sublime Text 3 publish both variants as separate ids
# (X and X.Portable); ST4 publishes only one, and it is the portable one. Kept
# anyway because the point is having `subl` on every machine's PATH. For the
# graphical launcher, see MANUAL_INSTALL.md.
SublimeHQ.SublimeText.4
Notepad++.Notepad++

# Messaging
# Rambox gathers the messengers and is what gets used daily. Native Telegram and
# WhatsApp are here as a fallback: when Rambox breaks or the machine acts up,
# not being cut off matters more than the convenience of one window.
Telegram.TelegramDesktop

# The next three come from the MICROSOFT STORE, not the winget catalogue, which
# is why their id is a Store Product ID instead of Publisher.Package.
#
# They also need a signed-in Store account, and winget does not say so: it
# reaches the Store catalogue without one, so the id resolves and only the
# download fails. install-packages.ps1 warns before installing and lists them
# apart in the summary for that reason.
#
# Checked on 2026-09-02 on a real machine, which was the open question: `winget
# list --id <StoreId> --exact` DOES detect them once installed, so
# Test-PackageInstalled works and the script does not reinstall them every run.
#
# They are MSIX, so they install per user: `--scope machine` fails, the script
# retries unconstrained, and they show up in the user-scoped report. That is the
# correct behaviour, not a fault.
9NKSQGP7F2NH   # WhatsApp
9P0KN9S5RP86   # Fantastical (Flexibits)

# Apple Devices succeeds iTunes at what iTunes did as a manager: backing up,
# restoring, updating and syncing iPhone and iPad from Windows. It is published
# ONLY through the Microsoft Store; the winget catalogue does carry Apple
# packages -Apple.iTunes, Apple.AppleMobileDeviceSupport- that are not this
# application. Id checked on 2026-09-09 against

9NP83LWLPZ9K   # Apple Devices
